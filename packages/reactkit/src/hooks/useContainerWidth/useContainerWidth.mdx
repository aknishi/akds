# useContainerWidth

> **Available from v1.8.0**

Returns an element's width in pixels, and re-renders whenever it changes. Use it for a threshold that isn't a breakpoint, such as the width a row of buttons needs to fit.

To switch layouts at a design system breakpoint, use [`useContainerBreakpointUp` or `useContainerBreakpointDown`](?path=/docs/reactkit-hooks-usecontainerbreakpointup-and-usecontainerbreakpointdown--docs) instead. They only re-render when the breakpoint is crossed, while `useContainerWidth` re-renders on every pixel of a resize.

## Usage

```tsx
import { useRef } from 'react';
import { useContainerWidth } from '@aknishi/akds-reactkit';

function Toolbar() {
  const ref = useRef<HTMLDivElement>(null);
  const width = useContainerWidth(ref);
  // The labelled buttons need 600px; below that, show a menu.
  const fits = width === null || width >= 600;
  return <div ref={ref}>{fits ? <ToolbarButtons /> : <ToolbarMenu />}</div>;
}
```

## Behavior

- **Content box:** the width is without padding, border, or a scrollbar: the same width a CSS container query compares.
- **Measured before the first paint:** the element is measured in a layout effect, so the first frame already has the width.
- **`null` before measuring:** during a server render, or while the ref has no element, the hook returns `null`. Decide which layout `null` gets, as in the example above.
- **Measure an element that doesn't depend on the result:** if the measured element's width changes with what you render inside it, the layout can flip back and forth. Measure a wrapper whose width comes from its parent.
- **The element has to stay the same:** the ref is read when the component mounts. If the element is replaced, give the component a new `key`.
